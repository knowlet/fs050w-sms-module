# FS050W 簡訊中心

這份工具讓 FS050W V2.1.0 的原廠管理首頁提供簡訊收發。手機連上 FS050W 的 Wi‑Fi，打開 [管理首頁](http://192.168.100.1/common/home.html)，從原廠選單的「首頁 → 簡訊中心」進入。電腦也用同一個網址。日常使用不需要另一台電腦持續開機，也不用安裝憑證。本套件只支援 SMS；RCS 仍屬研究方向，尚未實作。

> **安裝前先看**　首次安裝需要一台已連上 FS050W Wi‑Fi 的電腦、Python 3.10 以上版本，以及自己的管理密碼。安裝工具會使用本研究在 V2.1.0 驗證的 NTP 維護通道取得設備權限；出廠管理頁本身沒有上傳此模組的功能。若設備尚未啟用 `device_debug_mode`，必須明確選擇 `--enable-debug-mode` 或在互動模式中確認。這個標記可能擴大原廠網頁除錯功能的權限範圍。工具只接受已核對的 V2.1.0 韌體與原廠首頁，其他版本會停止。**一鍵安裝尚未在第二台實體設備驗證。**

## 怎麼使用

1. 手機連上路由器 Wi‑Fi，開啟 `http://192.168.100.1/common/home.html`。
2. 登入原廠管理頁，點左側「首頁 → 簡訊中心」。手機版先點原廠的選單圖示，再點「簡訊中心」；要離開時切換到側邊選單的其他項目。
3. 「全部」會列出 SIM 卡與設備中的訊息，也可以分別切換。點訊息即可讀取。按「撰寫簡訊」可輸入台灣手機號碼。發送本文目前支援 1 至 40 個英文字母、數字或空格。
4. 要刪除時，先點開那封訊息，再按「刪除這封簡訊」。確認視窗會列出儲存區、索引、寄件者與本文預覽。點「保留簡訊」就會返回，點「刪除」才會提交。

介面送出刪除前會重新讀取該位置，確認仍是同一封訊息。手機瀏覽器可把原廠首頁加入主畫面作捷徑。管理頁目前使用 HTTP，所以沒有 HTTPS 網站的完整離線 PWA 安裝能力；登入與簡訊內容也應只在自己信任的路由器 Wi‑Fi 上使用。收發簡訊仍需手機連上路由器的 Wi‑Fi。

## 其他 FS050W 如何安裝

在電腦上解壓縮 `FS050W-SMS.zip`，打開其中的 `FS050W-SMS` 資料夾，再執行下面其中一種方式。工具會請你輸入管理密碼，不會把密碼放進套件或儲存在設備上。

**一次完成：**若設備是原廠狀態，明確同意啟用前述 debug mode 後執行：

```sh
python3 install_via_ntp.py install --enable-debug-mode
```

若設備原本已有 `device_debug_mode` 標記與可用的開機掛鉤，可省略 `--enable-debug-mode`。想逐步看每項檢查並自行確認，則執行：

```sh
python3 install_via_ntp.py interactive
```

工具會從自己的設備讀取原版首頁，核對 V2.1.0、原廠檔案與安全狀態，準備專用安裝包，經 NTP 維護通道傳到設備，再由設備端核對韌體函式庫、備份原檔並啟動 SMS。若另一個程式已使用簡訊連線，或首頁已修改，安裝會停止。它不會關閉行動數據、變更 APN、按鍵、SIM 或數據機網域偏好。每次 NTP 短命令後都會讀回並還原原有時間伺服器設定。若自動找不到電腦的路由器 Wi‑Fi 位址，可在 `install` 或 `interactive` **前面**加上 `--host-ip <電腦的區域網路 IP>`；若電腦防火牆阻擋路由器下載安裝資料，也需允許這次暫時的本機傳輸。

安裝後重新開啟管理首頁，確認 SIM 與設備收件清單都能讀取，再用自己控制的第二支手機雙向測試。回復原首頁、模組，以及安裝器自己建立的開機標記／掛鉤：

```sh
python3 install_via_ntp.py rollback
```

需要檢查設備的維護者，也可使用 `python3 ntp_shell.py exec 'id -u'` 執行一條命令，或用 `python3 ntp_shell.py interactive` 進入互動終端。這是 root 維護通道，只應在自己的設備上使用。設備端的手動準備與安裝腳本仍包含在套件中，供已有 root 維護終端者使用。

NTP 維護通道已在這台研究設備用於讀取狀態與更新簡訊模組、管理頁，並確認結束後 NTP 設定還原。自動安裝與回復流程已通過離線及模擬檢查；尚未在第二台實體 FS050W 完整執行。其他設備的版本、原廠首頁與電信業者網路仍需各自驗證。

## 研究結果與修復範圍

| 看到的現象 | 在研究設備查到的原因 | 已驗證的改善 |
|---|---|---|
| 收件計數或清單回 `109` | 重啟後簡訊模組和它的連線沒有啟動 | 模組開機恢復後，SIM 與設備收件清單都正常 |
| 發送回 `610` | 追到數據機 `RAW_SEND` 回覆 `0x0038`（投遞失敗）；當時只有數據服務，LTE 沒有可用的簡訊通道 | 暫時改為數據與簡訊通道都啟用後，雙向收發成功；永久設定通過一次軟體重啟 |
| 重啟後訊息儲存位置不同 | 原廠收件路由會把普通訊息放在 SIM | 介面同時讀取 SIM 與設備儲存區 |
| 刪除時顯示模組需要更新 | 原廠刪除網址沒有回應緩衝區，無法回報是否刪除 | 新版透過帶明確標記的讀取通道送出單封刪除；研究設備已實際刪除一封指定的 SIM 測試訊息，並確認索引消失 |

`610` 是韌體把不同錯誤折疊後的回碼；路由檢查失敗也可能回 `610`，不能只靠這個數字判定。這台研究設備的詳細紀錄指向 `RAW_SEND`。修復包內的 `REPAIR.md` 會先檢查目前數據機讀值，再讓維護者決定是否試用 CS+PS；安裝首頁本身不會自動更改數據機網域。研究設備已確認寄出的測試簡訊在另一支手機收到，從手機回寄的訊息也在路由器逐字讀出。單封刪除已通過模擬數據機與無效請求測試，確認視窗的取消動作也經實際瀏覽器檢查。其後獲設備持有人同意，重讀並比對 `fs050w5` 內容後，向 SIM 索引 `0` 提交一次刪除；模組回 `retcode=0`、`deleted=1`、`rc=0`、`err=0`，再次查詢時 SIM 索引 `0` 已消失。設備儲存區的有效簡訊尚未實際刪除；完全斷電後的恢復情境與其他電信業者尚未實測。

本套件提供的 `sms.html` 是單檔介面，`repair-kit.zip` 含簡訊模組、診斷與回復工具。數據機診斷與修復細節見 [REPAIR.md](REPAIR.md)。
